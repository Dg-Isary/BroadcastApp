# 🎙️ 智能校园广播系统 - 移动对讲端 (BroadcastApp)

本仓库是 [智能校园广播系统 (BroadcastSystem)](https://www.google.com/search?q=%E9%93%BE%E6%8E%A5%E5%88%B0%E4%BD%A0%E7%9A%84%E5%90%8E%E7%AB%AF%E4%BB%93%E5%BA%93%E5%9C%B0%E5%9D%80) 的专属移动端配套应用。

它不仅可以将手机无缝转换为一个**极其安全的无线麦克风**，随时随地向全校或全公司发起实时广播，还内置了轻量级的 Web 播控中心，方便管理员在移动端单手掌控所有的打铃排程与音乐队列。

## ✨ 核心特性

* 🎤 **无线实时喊话**：打破传统广播室的物理空间限制。只需按住按钮，手机麦克风采集的音频将以极低的延迟推送到服务器主控端进行全区广播。
* 🛡️ **金融级混合加密 (RSA + AES)**：由于校园/企业广播涉及极高的安全权限，本应用采用了极其严苛的安全通信协议。
* **动态秘钥**：App 每次发起广播前，会从服务端动态拉取 RSA 2048 公钥。
* **信道加密**：在手机端本地随机生成 AES 密钥，利用 AES-CTR 对音频流进行毫秒级流式加密，再用 RSA 将 AES 密钥加密后一同通过 TCP 7000 端口发送给服务器。彻底杜绝局域网抓包监听与恶意音频注入！


* 📱 **一体化播控中枢**：深度集成了服务端的 `mobile.html` 自适应看板。支持一键切歌、音量调节、队列管理及紧急系统静音。

## 🛠️ 编译与运行说明

### 1. 开发环境准备

* 确保已安装最新版的 Android Studio (或相应的跨平台开发环境)。
* 确保已配置好 Android SDK，且目标 SDK 版本（Target SDK）满足当前主流设备要求。

### 2. 与服务端对接配置

在运行本 App 之前，请确保你的 **BroadcastSystem** C# 服务端已经在局域网或公网中运行，并记录下服务端的 IP 地址。

* **TCP 端口**：本 App 默认向服务端的 `7000` 端口发送加密音频流。
* **API 端口**：本 App 默认向服务端的 `5000` 端口请求状态和控制命令。
*(请务必确保服务端电脑的防火墙已放行这两个端口！)*

### 3. 权限要求

由于需要实时采集音频并进行网络传输，首次打开 App 时，请授予以下必要权限：

* 🎤 `RECORD_AUDIO` (麦克风录音权限)
* 🌐 `INTERNET` (网络访问权限)

## 📖 使用说明

### 1. 登录与连接

* 打开 App，在设置页面或初始弹窗中输入服务端的主机 IP（例如 `192.168.1.100`）。
* 如果服务端开启了安全锁，请在界面提示“访问受限”时，输入管理员密码完成解锁认证。

### 2. 实时安全广播 (对讲模式)

* 进入对讲页面，长按**“按住说话”**按钮即可开始录音。
* 系统会在后台瞬间完成“拉取公钥 -> 生成 AES 密钥 -> 混合加密 -> TCP 推流”的复杂动作。
* 松开按钮，广播即刻结束。

### 3. 远程排程与播控

* 切换到**“控制台”**面板，你将看到一个高度适配手机屏幕的播控界面。
* 你可以随时添加临时音乐、跳过当前曲目、或者直接点击右上角的“排程”查看今天的打铃任务。
* 遇到突发情况，直接点击下方的 **“红色停止按钮”**，服务端将瞬间切断所有声音。

## ⚠️ 注意事项与常见问题

1. **公钥拉取失败**：如果在对讲时提示“无法获取安全公钥”，请检查手机与服务器是否在同一局域网内，以及服务端的 `5000` 端口是否被拦截。
2. **音频卡顿问题**：加密音频流通过 TCP 传输，如果局域网内 Wi-Fi 信号极差或存在严重丢包，可能会导致服务端缓冲不足。建议在稳定的无线网络下使用喊话功能。
3. **隐私声明**：本 App 的录音行为仅在您“主动按住”对讲按钮时发生，且音频数据在离开手机内存前已被强加密，绝不在本地留下任何明文录音文件。
